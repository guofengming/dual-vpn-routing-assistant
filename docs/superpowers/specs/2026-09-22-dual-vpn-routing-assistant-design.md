# 双 VPN 分流助手设计说明

- 日期：2026-09-22
- 状态：用户已确认，已实现
- 目标仓库：`guofengming/dual-vpn-routing-assistant`（GitHub 私有仓库）
- 目标平台：macOS 13 及以上，Apple Silicon 与 Intel

## 1. 背景

中移 ZYZXVPN 会在活动的 `utun` 接口上安装 `10.0.0.0/8` 路由，并让 AccessClient、VMware Horizon 等中移动业务继续使用该隧道。与此同时，度管家和普通百度内网访问需要通过办公网络的物理默认网关，并使用企业分流 DNS。

现有 `baidu-mobile-dual-vpn` Skill 已验证以下规则可行：

- `10.0.0.0/9` 和 `10.128.0.0/9` 经当前物理默认网关访问；
- 中移 DNS `10.57.0.96`、`10.57.0.196` 固定经当前中移 `utun`；
- `baidu.com`、`baidu-int.com`、`internal.baidu.com` 使用企业 DNS `172.31.5.60`、`172.31.6.60`；
- `family.baidu.com` 应解析为 `10.11.*`，并能访问企业后端。

现有自动化脚本会读取中移客户端留下的 `secureutun.plist`。当 VPN 已断开而 plist 仍保存旧接口名时，脚本可能继续尝试向不存在的 `utun` 写路由，产生 `route: bad address`，并可能让网络切换后的度管家恢复不稳定。

本项目将上述能力做成独立 macOS App，不再依赖 Codex Skill，并增加明确的网络状态机、安全恢复、诊断界面和可分发安装包。

## 2. 目标与非目标

### 2.1 目标

1. 中移 VPN 与度管家可以同时正常使用。
2. 中移 VPN 上线、下线、重连或更换 `utun` 后自动校正路由和 DNS。
3. Wi-Fi、有线网络、默认网关变化和睡眠唤醒后安全重置，并在网络稳定后恢复分流。
4. 中移 VPN 未连接时安静等待，不写无效路由，不持续打印错误。
5. 提供暂停、恢复、立即检测并修复、诊断日志和开机自动分流设置。
6. 首次安装后日常操作无需管理员密码。
7. 生成可供同事下载的 macOS 通用 `.dmg`，并通过私有 GitHub Releases 分发。

### 2.2 非目标

1. 不负责启动、关闭或登录中移 VPN。
2. 不负责启动、关闭或登录度管家。
3. 不修改 AccessClient、VMware Horizon 或其他 VPN 客户端本身。
4. 不实现通用 VPN 路由编辑器；首版只支持已确认的百度办公网与中移 VPN 场景。
5. 首版不做 Apple Developer 签名、公证和自动在线升级。
6. 不上传遥测、网络内容、账号信息或诊断数据。

## 3. 用户体验

### 3.1 应用形态

应用为完整窗口，不使用仅菜单栏形态。窗口采用侧边导航：

- 状态
- 诊断日志
- 设置

视觉采用“深空蓝 · 精密仪表”方向：冷蓝高亮、细网格、轻量发光、方形切角和清晰的链路状态。界面同时适配 macOS 浅色与深色外观，科技感不以牺牲可读性为代价。

### 3.2 状态页

状态页展示：

- 总体状态：未安装、等待中移 VPN、检测中、分流正常、网络切换恢复中、已暂停、需要处理；
- 当前物理接口与网关；
- 当前中移 `utun`；
- 百度内网路由与企业 DNS 状态；
- 中移 DNS 主机路由状态；
- 最近一次检查与最近一次网络变化；
- “暂停自动分流”或“恢复自动分流”；
- “立即检测并修复”。

状态页只观察 VPN，不提供任何 VPN 启停或登录按钮。

### 3.3 诊断日志页

诊断页展示结构化事件，不直接堆叠全部命令输出：

- 时间；
- 状态变化；
- 检测结果；
- 实际执行的受管操作；
- 验证结果；
- 用户可执行的建议。

支持复制诊断摘要和导出脱敏日志。导出时隐藏用户名、用户目录和非必要的本机标识；已确认的企业网络地址保留，以便排障。

### 3.4 设置页

设置项包括：

- 开机自动启用分流，默认开启；
- 日志详细程度：标准或详细，默认标准；
- 卸载后台服务。

后台 LaunchDaemon 安装后始终可被系统加载，以保证日常恢复无需再次授权。“开机自动启用分流”关闭时，服务在开机后进入暂停态，不修改网络；用户从 App 恢复时无需管理员密码。

## 4. 系统架构

系统由三个边界清晰的单元组成。

### 4.1 Electron App

职责：

- 展示状态、诊断和设置；
- 发出固定类型的控制请求；
- 首次安装、版本升级和卸载时触发 macOS 管理员授权；
- 不直接执行 root 路由或 DNS 命令。

Electron 安全设置：

- `contextIsolation: true`；
- `nodeIntegration: false`；
- `sandbox: true`；
- preload 只暴露固定 API；
- renderer 不接收任意命令、路径或 shell 参数；
- 使用严格 Content Security Policy，不加载远程脚本。

### 4.2 Root LaunchDaemon

标识：`com.guofengming.dual-vpn-routing-assistant`

职责：

- 观察物理网络、中移 VPN、路由和 DNS 状态；
- 执行状态机；
- 只管理本应用声明的路由和 supplemental DNS；
- 保存安装前快照和每次应用的受管项清单；
- 执行验证、回滚和日志轮转；
- 将只读状态写给 Electron App。

建议安装位置：

- 执行文件：`/Library/Application Support/DualVPNRoutingAssistant/bin/`
- 配置与通信：`/Library/Application Support/DualVPNRoutingAssistant/`
- 持久状态：`/var/db/dual-vpn-routing-assistant/`
- 日志：`/var/log/dual-vpn-routing-assistant.log`
- plist：`/Library/LaunchDaemons/com.guofengming.dual-vpn-routing-assistant.plist`

### 4.3 安装与卸载程序

安装程序以固定参数执行随 App 打包的脚本，并通过 macOS 标准管理员授权提升权限。它负责：

1. 检测旧 Skill 服务；
2. 若存在旧服务，使用 App 内置、固定白名单目标的兼容恢复逻辑读取并恢复旧快照；不得以 root 执行用户目录中的 Skill 脚本；
3. 验证旧网络状态已恢复，但保留旧服务文件和备份；
4. 保存新版首次接管前的路由、DNS 快照；
5. 安装新版服务文件和 LaunchDaemon；
6. 启动后台服务并回读版本、状态完成验证；
7. 新版验证成功后才删除旧资产；任一步失败都恢复并重新加载旧 LaunchDaemon。

安装程序不接受 renderer 传入的命令文本或任意文件路径。

同事电脑通常没有旧 Skill，因此直接执行新版安装。若检测到旧服务，统一使用应用内置、与旧卸载能力等价的兼容清理流程，不信任或执行用户目录中的代码。

## 5. App 与后台服务通信

首版不引入原生 Swift 特权 helper，而使用严格受限的 JSON 文件协议。

请求类型仅允许：

- `repairNow`
- `setPaused`
- `setAutoEnableAtBoot`
- `setLogLevel`

每个请求只包含协议版本、请求类型、请求 ID、布尔值或枚举值和时间戳。协议不支持命令、路径、环境变量或自由文本参数。

安全约束：

- root 创建每用户通信目录，并将目录所有者设置为当前控制台用户，权限为 `0700`；
- App 使用临时文件加原子硬链接发布请求，绝不覆盖待处理请求；daemon 先把请求移入 root 隔离区，再校验并重建只含白名单字段的 root 记录；
- daemon 拒绝符号链接、错误所有者、宽松权限、未知字段和无效枚举；
- 每个请求 ID 只处理一次；
- 状态文件由 root 原子写入，普通用户只读；
- daemon 只接受当前控制台用户的请求。

Electron 每秒读取轻量状态文件。后台网络检查采用事件触发加低频兜底检查，空闲状态下不反复执行路由写操作。

## 6. 网络识别与受管配置

### 6.1 物理网络

物理网络必须满足：

- 接口存在且不是 `utun`；
- 存在有效默认网关；
- 至少一个企业 DNS 可通过该接口访问 TCP 53；
- 网关和接口组合已稳定至少 3 秒。

任何条件不满足时都不写入路由。

### 6.2 中移 VPN

读取当前控制台用户的：

`~/Library/Application Support/com.chinamobileonline.vpnclientx/secureutun.plist`

plist 中的接口名只能作为候选。正式使用前必须验证：

- 接口当前真实存在；
- 接口为 `utun`；
- 接口处于活动状态并拥有地址；
- 中移 DNS 路由可以绑定到该接口。

因此，断线后遗留的 `utun4` 等旧值不会触发路由写入。

### 6.3 受管路由和 DNS

应用只管理：

- `10.0.0.0/9` → 当前物理默认网关；
- `10.128.0.0/9` → 当前物理默认网关；
- `10.57.0.96/32` → 当前中移 `utun`；
- `10.57.0.196/32` → 当前中移 `utun`；
- supplemental DNS 域名：`baidu.com`、`baidu-int.com`、`internal.baidu.com`；
- supplemental DNS 服务器：`172.31.5.60`、`172.31.6.60`。

应用不删除或修改其他 VPN、用户或系统创建的路由。

### 6.4 验证

应用完成配置后验证：

1. 两条 `/9` 路由使用当前物理接口和网关；
2. 两个中移 DNS 主机路由使用当前有效 `utun`；
3. `family.baidu.com` 解析结果包含 `10.11.*`；
4. `10.11.154.217` 或 `10.11.173.70` 至少一个可访问 TCP 443；
5. 中移 VPN 接口仍存在，未被本应用改写默认路由。

## 7. 状态机与自动恢复

### 7.1 状态

- `UNINSTALLED`：后台服务不存在；
- `IDLE`：服务运行，但中移 VPN 未连接；
- `PROBING`：正在确认物理网络、企业 DNS 和中移接口；
- `ACTIVE`：路由、DNS 和验证均正常；
- `NETWORK_SETTLING`：检测到网络或网关变化，正在等待稳定；
- `REPAIRING`：正在执行用户触发或自动修复；
- `PAUSED`：受管配置已撤销，服务不修改网络；
- `DEGRADED`：连续修复失败，停止主动写入并等待环境变化或用户操作。

### 7.2 中移 VPN 上线

1. 从 `IDLE` 进入 `PROBING`；
2. 验证物理网络、企业 DNS 和真实存在的 `utun`；
3. 保存必要快照；
4. 幂等地应用受管路由与 DNS；
5. 完成业务验证；
6. 成功进入 `ACTIVE`，失败时安全回滚并进入 `DEGRADED`。

### 7.3 中移 VPN 下线

1. 发现当前受管 `utun` 消失；
2. 删除本应用创建的 `/9`、中移 DNS 主机路由和 supplemental DNS；
3. 在仍有效时恢复安装前同名项；
4. 清理 DNS 缓存；
5. 进入 `IDLE`，不再尝试写入旧接口。

### 7.4 网络切换

物理接口、默认网关或网络签名变化时：

1. 进入 `NETWORK_SETTLING`；
2. 立即撤销本应用当前管理的路由和 DNS；
3. 等待新网络稳定，最长 30 秒；
4. 重新识别企业 DNS 与中移接口；
5. 条件满足时使用新网关重新应用并验证；
6. 条件不满足时保持干净网络状态，不强行恢复旧网关。

这一过程允许百度内网短暂中断 10–30 秒，以优先保证度管家能够在新网络环境中重新连接。

### 7.5 重试策略

单次状态变化先做 3 秒去抖。失败后按 2 秒、5 秒、10 秒重试，最多三次。连续失败进入 `DEGRADED`，直到以下任一条件发生：

- 物理网络变化；
- 中移接口变化；
- 用户点击“立即检测并修复”；
- 用户暂停后恢复。

该策略避免无限重试、断网和日志刷屏。

### 7.6 暂停和恢复

暂停时：

- 撤销本应用管理的路由和 DNS；
- 恢复仍然有效的安装前快照；
- 后台服务继续运行但不修改网络。

恢复时重新从 `PROBING` 开始，不复用旧网关或旧 `utun`。

## 8. 快照、回滚与卸载

首次安装保存 root 所有、权限 `0700` 的原始快照。每次应用配置还保存当前受管项清单，确保只撤销本应用实际创建或替换的内容。

恢复路由前必须验证快照中的接口和网关仍然存在。若快照已因网络切换失效，则删除本应用创建的项但不重新写入旧网关，并在日志中说明。

卸载流程：

1. 进入暂停并撤销受管配置；
2. 恢复仍有效的安装前快照；
3. 停止并移除 LaunchDaemon；
4. 删除后台执行文件、配置、状态和快照；
5. 保留一份最终卸载摘要供界面显示；
6. 提示用户将 App 拖入废纸篓。

## 9. 错误处理

所有写操作遵循“验证前置、修改最小、失败回滚”：

- 无物理网关：保持不变并等待；
- 企业 DNS 不可达：保持不变，不安装分流 DNS；
- plist 存在但 `utun` 不存在：视为 VPN 未连接；
- 路由已正确：不重复写入；
- DNS 验证失败：撤销本轮 DNS 修改；
- 部分路由写入失败：撤销本轮已写入项；
- 状态文件损坏：忽略并重建，不执行未知请求；
- 连续失败：进入 `DEGRADED`，停止主动写入；
- App 崩溃：daemon 独立运行，不影响已建立的分流；
- daemon 崩溃：LaunchDaemon 拉起后先重新探测，不盲目复用旧状态。

## 11. 测试策略

### 11.1 单元测试

- `route -n get`、`ifconfig`、`scutil` 和 plist 输出解析；
- 物理接口与中移接口判定；
- 请求 JSON schema 和权限校验；
- 状态机转换、去抖和重试上限；
- 快照有效性和受管项差异计算；
- 日志脱敏。

### 11.2 模拟集成测试

使用固定命令输出样本覆盖：

- 中移 VPN 上线与下线；
- plist 指向不存在的旧 `utun`；
- `utun4` 重连后变为其他编号；
- Wi-Fi 切换导致接口或网关变化；
- 企业 DNS 暂时不可达；
- DNS 解析不是 `10.11.*`；
- 路由部分写入失败；
- 连续修复失败进入 `DEGRADED`；
- 暂停、恢复、重启和卸载。

### 11.3 真机验收

至少在一台 Apple Silicon Mac 完成完整企业 VPN 验收，并在 Intel Mac 或可用 Intel 测试机上完成安装、启动和基本路由引擎验证。还需在 macOS 13 真机完成安装、首次启动、后台服务启动、暂停/恢复和卸载的最低系统版本冒烟测试；若暂时没有对应真机，发布说明必须明确标注该项尚未完成，不能声称已完成 macOS 13 真机验证。

真机验收项目：

1. 中移 VPN 未连接时不修改网络、不刷错误；
2. 中移 VPN 连接后，度管家、百度内网、AccessClient 或 Horizon 可同时使用；
3. 中移 VPN 断开后，度管家仍可连接；
4. 切换 Wi-Fi、有线网络或睡眠唤醒后约 30 秒内恢复；
5. 暂停后恢复原网络状态，恢复后重新分流；
6. “立即检测并修复”能纠正受管路由或 DNS 漂移；
7. 重启系统后后台服务运行但不弹 App；
8. 关闭“开机自动启用分流”后，重启进入暂停态；
9. 升级保留设置；
10. 卸载恢复网络并删除后台服务；
11. GitHub Release 中的 Universal `.dmg` 可下载、校验并安装。

企业 VPN 的最终业务连通性无法在 CI 中模拟，必须以真机验收为准。

## 12. 验收标准

项目完成必须同时满足：

- 所有自动化测试通过；
