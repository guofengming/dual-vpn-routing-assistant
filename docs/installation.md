# 双 VPN 分流助手使用说明

本文面向日常使用者，说明如何在 macOS 上安装、启用、诊断、升级和卸载“双 VPN 分流助手”。

## 1. 适用范围

本助手用于以下场景：

- 中移 ZYZXVPN 负责 AccessClient、VMware Horizon 等中移专用业务。
- 百度办公网和度管家需要继续通过当前物理网络访问。
- 切换 Wi-Fi、有线网络、睡眠唤醒或 VPN 重连后，希望分流能自动恢复。

系统要求为 macOS 13 或更高版本。发布包为 Universal DMG，同一个安装包同时包含 Apple 芯片（`arm64`）和 Intel（`x86_64`）版本，不需要分别下载两个包。

本助手只管理固定范围的路由和补充 DNS，不会启动、关闭、登录或退出 ZYZXVPN、度管家、AccessClient、VMware Horizon。是否运行和登录这些应用始终由用户自己决定。

## 2. 使用前准备

安装前请确认：

- 已安装并能正常登录中移 ZYZXVPN 和度管家。
- 当前账号有 macOS 管理员授权；安装、升级和卸载后台服务时需要输入管理员密码。
- 能访问公司办公网络，或已连接能访问百度办公网的网络环境。
- 从项目公开的 GitHub Releases 页面下载安装包，不使用聊天附件或来源不明的构建包。

如果电脑上安装过旧版 `baidu-mobile-dual-vpn` Skill 的自动分流服务，可以直接安装 App，不需要先手工卸载旧服务。迁移只会在 App 内点击“安装后台服务”时发生；仅把 App 拖入“应用程序”不会修改现有网络。

## 3. 下载

1. 打开公开的 [GitHub Releases 页面](https://github.com/guofengming/dual-vpn-routing-assistant/releases/latest)，无需登录 GitHub。
2. 在最新版的 `Assets` 区域下载 `双-VPN-分流助手-<版本>-universal.dmg`。

## 4. 安装无签名应用

首版为无签名、未公证构建，第一次打开时需要在 macOS 中人工确认，这是预期的安装流程。

1. 打开 DMG。
2. 将“**双 VPN 分流助手**”拖入“应用程序”文件夹。不要直接从 DMG 中长期运行。
3. 从“应用程序”打开助手。
4. 如果系统提示无法验证开发者，关闭提示。
5. 打开“系统设置 → 隐私与安全性”，在安全性区域找到被拦截的应用并点击“仍要打开”。
6. 再次确认打开应用。

如果没有看到“仍要打开”，请先重新尝试从“应用程序”打开一次，再返回“隐私与安全性”。

## 5. 首次启用

1. 打开助手，状态页会显示“后台服务尚未安装”。
2. 点击“安装后台服务”。
3. 按 macOS 提示输入管理员密码。
4. 等待安装完成，不要在授权过程中关闭窗口。
5. 自己打开并登录度管家和中移 ZYZXVPN。
6. 助手会依次显示“正在检测网络”“网络正在重新校准”等状态；成功后显示“分流矩阵稳定”。

后台服务安装后会随系统加载，并在网络变化时自动检查和修复。助手窗口本身不会随开机自动弹出，两个 VPN 应用也不会被助手自动启动。

日常检测、暂停和恢复不需要重复输入管理员密码。安装、升级或卸载后台服务时才会再次请求授权。

打开 App 后，macOS 顶部菜单栏会显示分流助手图标。关闭主窗口只会将窗口隐藏，菜单栏图标和后台服务会继续运行；需要重新打开窗口时，点击菜单栏图标即可。菜单栏图标不会随系统自动出现，重启电脑后如需使用快捷操作，请手工打开一次 App。后台分流服务是否自动启用仍由 App 设置页独立控制。

### 已安装旧 Skill 时

安装器检测到旧版自动分流服务后会执行事务式迁移：

1. 备份旧 LaunchDaemon、系统脚本以及路由和 DNS 快照。
2. 停止旧后台服务，并使用 App 自带的固定逻辑恢复旧服务管理的网络配置；不会以管理员身份执行用户目录中的 Skill 脚本。
3. 安装并启动新后台服务，验证其运行状态和版本。
4. 只有新服务验证成功后，才删除旧服务的系统级文件和快照。

如果任一步失败，安装器会停止新安装并尝试恢复旧服务，不会让两个自动分流服务同时运行。迁移成功后，不要再执行旧 Skill 的 `install-auto-reclaim.sh`、`uninstall-auto-reclaim.sh` 或路由修复脚本；需要暂停、修复或卸载时统一使用 App。

App 只移除旧 Skill 安装到 `/Library/LaunchDaemons`、`/usr/local/libexec` 和 `/var/db` 的系统级服务，不会删除用户目录中的 Codex Skill 源文件。

## 6. 推荐使用流程

日常使用时不要求固定的 VPN 启动顺序：

1. 按自己的习惯打开并登录度管家和中移 ZYZXVPN。
2. 等待助手识别当前物理网关和中移隧道。
3. 状态显示“分流矩阵稳定”后，再使用百度办公网、中移专用业务、AccessClient 或 VMware Horizon。

中移 VPN 没有连接时，助手通常显示“等待中移 VPN”，并保持网络原状。这不是故障，也不需要卸载或停止后台服务。

## 7. 页面和常用操作

### 状态页

- 查看当前物理出口、物理网关和中移隧道。
- 查看办公网、中移 DNS 和补充 DNS 是否处于预期路径。
- 点击“立即检测并修复”，重新探测当前网络并修复分流。
- 点击“暂停分流”，撤销本助手管理的路由和 DNS；这不会关闭两个 VPN 应用。
- 暂停后点击“恢复分流”，重新进入探测和应用流程。

### 诊断日志

- “复制摘要”用于快速复制当前状态。
- “导出脱敏诊断”用于生成可交给维护者的诊断文件。
- “最近事件”最多显示 200 条结构化事件。

### 设置

- “开机自动启用分流”默认开启。关闭后，后台服务仍随系统加载，但保持暂停状态，不写入受管路由或 DNS。
- “日志详细度”可设为“标准”或“详细”。详细模式会增加探测信息，但不会记录网络内容或 VPN 凭据。
- “卸载后台服务”用于安全撤销配置并移除系统服务。

### 菜单栏快捷操作

- 单击菜单栏图标可重新打开并聚焦主窗口。
- 右键菜单可查看当前状态、执行“立即检测并修复”以及暂停或恢复分流。
- “退出应用”只退出窗口和菜单栏图标，不会停止、暂停或卸载后台服务。
- 关闭主窗口不会退出应用；需要完全退出界面时，请使用菜单栏中的“退出应用”。

## 8. 状态说明

| 界面状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 后台服务尚未安装 | App 已打开，但系统服务尚未安装 | 点击“安装后台服务”并完成管理员授权 |
| 等待中移 VPN | 尚未发现可用的中移隧道，网络保持原状 | 如需分流，请自行登录中移 VPN；否则无需处理 |
| 正在检测网络 | 正在确认物理网关、中移隧道和办公 DNS | 等待检测完成 |
| 网络正在重新校准 | 网络刚发生变化，旧配置已清理，正在等待新网络稳定 | 通常等待 10–30 秒 |
| 正在自动修复 | 发现配置漂移，正在进行受限重试 | 等待完成；长时间未恢复可手工检测 |
| 分流矩阵稳定 | 当前路由和 DNS 已通过检查 | 可以正常使用 |
| 分流已暂停 | 本助手管理的配置已撤销 | 需要时点击“恢复分流” |
| 需要处理 | 自动恢复没有完成，或检测到安全边界外的路由状态 | 查看诊断并执行“立即检测并修复” |

## 9. 切换网络或 VPN 后的处理

当 Wi-Fi、有线网络、物理网关或中移隧道发生变化时，助手会先撤销上一网络的受管配置，再等待新网络稳定后重新应用。期间办公网可能短暂中断 10–30 秒。

如果切网后度管家或百度办公网仍无法连接：

1. 等待 30 秒。
2. 确认当前 Wi-Fi 或有线网络本身可用。
3. 确认度管家和中移 VPN 都已由你自己正常登录。
4. 打开助手，点击“立即检测并修复”。
5. 仍未恢复时，打开“诊断日志”，先查看错误代码，再导出脱敏诊断交给维护者。

不要为了临时恢复而反复安装、卸载后台服务，也不要同时运行旧 Skill 脚本手工改路由；这会增加判断当前路由归属的难度。

如果中移 VPN 已关闭，可以保留后台服务运行。助手会回到“等待中移 VPN”，无需执行卸载。

## 10. 暂停与自动启用

需要暂时停用分流时，优先使用“暂停分流”，而不是卸载：

- 暂停会安全撤销本助手管理的路由和 DNS。
- 暂停不会退出或关闭度管家和中移 VPN。
- 恢复后会重新探测当前网络，不复用旧网关或旧隧道。

如果不希望重启电脑后自动启用，可在“设置”中关闭“开机自动启用分流”。后台服务仍会保留，以便随时从 App 恢复。

## 11. 升级

1. 从同一 GitHub 仓库的 Releases 下载新版本 DMG。
2. 从菜单栏图标中选择“退出应用”，确保当前 App 已完全退出。
3. 用新版本覆盖“应用程序”中的旧版本。
4. 打开新版本。如果 App 与后台服务版本不一致，状态页会显示“升级后台服务”。
5. 点击升级并完成管理员授权。
6. 等待新服务通过启动和网络状态检查。

不要只覆盖 App 后长期忽略“升级后台服务”提示；窗口和后台服务应保持版本一致。

## 12. 卸载

不要直接把 App 扔进废纸篓。请先安全卸载后台服务：

1. 打开助手的“设置”。
2. 点击“卸载后台服务”。
3. 阅读确认提示并点击“确认卸载”。
4. 输入管理员密码。
5. 确认界面回到“后台服务尚未安装”。
6. 再将“应用程序”中的 App 移到废纸篓。

卸载会先恢复或安全移除本助手管理的路由和 DNS，再移除后台服务。中移 VPN、度管家及其他业务应用不会被卸载。

如果卸载提示网络清理失败，不要直接删除 App 或后台文件。请先导出脱敏诊断，由维护者确认受管配置已经恢复后再继续。

## 13. 故障排查

### 一直停留在“等待中移 VPN”

- 确认中移 ZYZXVPN 已登录并真正建立隧道。
- 确认当前网络允许访问中移 VPN。
- 点击“立即检测并修复”。

### 长时间停留在“网络正在重新校准”

- 确认 Wi-Fi 或有线网络已获得有效网关。
- 避免在 30 秒内连续切换多个网络。
- 网络稳定后点击“立即检测并修复”。

### 显示“需要处理”

- 先查看状态页的错误信息和“诊断日志”中的最近事件。
- 点击一次“立即检测并修复”，等待本轮检测结束。
- 若仍未恢复，导出脱敏诊断交给维护者，不要自行删除系统目录中的状态文件。

### App 显示需要升级

说明 App 与后台服务版本不一致。点击“升级后台服务”并完成管理员授权即可。

### 需要向维护者提供什么

请提供：

- App 版本和 macOS 版本。
- Mac 是 Apple 芯片还是 Intel。
- 故障发生前是否切换过 Wi-Fi、有线网络或 VPN。
- “导出脱敏诊断”生成的文件。

无需提供 VPN 密码、账号口令、浏览器数据或业务网络内容。

## 14. 安全与隐私

- 不包含遥测，不上传使用数据。
- 不采集网络内容、浏览器数据或 VPN 凭据。
- 诊断文件只包含结构化状态和分流事件，并对用户名和用户目录进行替换。
- 日常 App 操作通过固定请求协议交给后台服务处理，普通用户界面不会直接执行任意管理员命令。
- 后台服务只维护产品声明的固定路由和补充 DNS 范围；发现路由归属不明确时会停止自动覆盖并显示“需要处理”。

## 15. 当前验证范围

版本 `0.2.0` 已完成自动化测试、Electron 窗口与菜单栏测试、Apple 芯片本机打包检查、DMG 完整性检查和 Universal 二进制架构检查。

以下项目仍应在正式推广前由获授权的测试设备完成：

- Apple 芯片 Mac 上的企业网络、中移 VPN 与度管家完整实网流程。
- Intel Mac 上的实际启动、后台服务和企业网络流程。
- macOS 13 实体机上的首次安装、升级和卸载流程。

因此，首轮建议先小范围试用。出现异常时优先暂停分流并导出诊断，不要手工删除受管路由或后台服务文件。
